# Shared building blocks

Cross-cutting pieces used by most screens. Moved from CLAUDE.md on 2026-11-15 (token pass); CLAUDE.md keeps a one-paragraph index.

- **Confirmations:** `confirmToast.*` / `blockedToast(name)` from `@/copy` — one wording per action; inside a sheet close first, then `showToastAfterSheet(...)`. Dev switches (map offline, check-in distance) live in `src/lib/devSimulation.ts`.
- **Guest mode:** `useGuestMode` (in-memory store in `src/components/map/hooks/`) gates account actions → `SignInPrompt` (routes to `/login`/`/register` via `resetTo`) or `GuestLock`. Guests can read chats but not send. An account-only page wraps its body in `GuestPage` (`src/components/GuestPage.tsx`, review 2026-11-18 IJ2/IJ22): a guest sees the page title, a lock message and Logg inn, never the content (Chat tab, Mine planer, Varsler, Betaling, Samarbeid and the Arbeidsflate pages); the Chat tab and the profile bell show no count for a guest. `signOut()` turns guest mode on and resets the session's stores (IJ1), so a deep link after logout shows the guest state, not the last account. Founder 2026-11-19 Q1/Q2 (0504): a guest browses only; a personal action on a readable page goes through `useGuestGate` (`gate(action, fn)` + one `prompt`), and sign-in lands where it was asked for: `SignInPrompt` remembers the spot (`src/lib/signInReturn.ts`: the route in front from the root layout's `RouteTracker`, the map's open place or experience as `/map?focus=`), and every step that starts a session calls `startSession()` instead of `resetTo("/map")`.
- **Demo stores:** `useMapSaved` (shared by map Lagret mode, swipe, place deck, `/saved`), `useGuestMode`, `useRecentSearches`, `usePinnedChats` (Chat's "Festet", Phase 18), `useMyRatings` (a sent "Hvordan var det?" on its plan) — zustand stores (P6) that reset on reload (persistence is contract-blocked). Exception (founder 2026-11-07): device choices — the Kartlag map type and style (`src/lib/mapChoice.ts`), Tilgjengelighet (`src/lib/a11yPrefs.ts`) and which one-time hints the phone has shown (`src/lib/hints.ts`, Phase 16; `HintBanner` shows one, `claimHint` allows one per session and must run only while the screen is in front, since the map pre-renders Sveip), the app version it last ran (Phase 18, `src/lib/whatsNew.ts`) and Utseende's System/Lys/Mørk choice (user request 2026-11-24, `src/theme/scheme.ts`, picked in Innstillinger's `ThemeSheet`) — are kept on the phone by `src/lib/deviceSettings.ts` (AsyncStorage, one key, read behind the root font gate); nothing about the account or its content is stored on the device.
- **Action sheets** [src/components/actions/ActionSheets.tsx](src/components/actions/ActionSheets.tsx) (Del/Rapporter/Blokker/Forlat/Venteliste/Pay/Avlys/plass ledig/Rate, and `ItemActionsSheet` for long-press quick actions on rows (Lagret, Chat: `ListRow onLongPress`, also a "Flere valg" accessibility action; on Android those two lists show the platform popup menu through `ContextMenu` (`src/components/actions/ContextMenu.tsx`, @react-native-menu/menu anchored by a 1 px view under the row, P10 user 2026-11-16), iOS, web and dev clients without the native view keep the sheet; the map’s browse cards have none since 2026-11-09); Del regningen, Belønninger and the payout schedule are hidden as V1 non-goals, founder 2026-11-07), **pickers** [src/components/pickers/Pickers.tsx](src/components/pickers/Pickers.tsx) (place/category/user + `SearchField`), `StateView`/`EmptyState` (optional second action), `Toast` (`showToast()`, sonner-native underneath since P4 with our card; host in root layout renders _under_ Modals on Android — call only from screen-level actions).
- **Who's going (founder 2026-11-07, opt-in per person):** `src/lib/going.ts` (`goingFor`: faces only for attendees who chose "Vis meg som deltaker", count = everyone going; the viewer's own switch is in memory), `useGoing` (live with the viewer's join) and `GoingLine` / `FaceStack` on the Sveip card, browse card and join card. The public "Se deltakere" names the host and the people who opted in; the host's Administrer list (sheet kind `guests`) names everyone.
- **Legg til i kalender:** `AddToCalendarLink` → `src/lib/addToCalendar.ts`: the phone's calendar app with the event filled in (expo-calendar's system-UI call, imported from `expo-calendar/legacy` since SDK 57; loaded lazily and guarded). No calendar permission: `app.json` blocks READ/WRITE_CALENDAR on Android.
- **Åpent nå:** read from a place's `hours` at the moment it is shown (`isPlaceOpen`, `src/lib/openingHours.ts`: day ranges, "og", "Hver dag", minutes, past midnight, "Første fredag i måneden", "Alltid åpent", and special days such as "Stengt 17. mai"); `openNow` is only the fallback for hours it can't read. The place page, map sheet, browse meta, Sveip card and Filtre's "Åpent nå" all use it.
- **Veibeskrivelse:** `DirectionsButton` (`src/components/DirectionsButton.tsx`) → `src/lib/directions.ts`: the route in the phone's maps app (Google Maps URL on Android, Apple Maps on iOS); only the destination coordinate leaves the app.
- **Du er med / Få hjelp (Phase 18):** `JoinedSheet` (`src/components/experience/`) opens after Bli med (after the pay sheet for paid ones) with the time, the meeting point, Legg til i kalender, Veibeskrivelse and Til samtalen. "Få hjelp" on plan rows and the experience page opens `/settings/support?about=<experience id>` (`SupportFormScreen`, prefilled); Hjelp og støtte opens it empty.
- **Unsaved changes (Phase 18):** `useConfirmLeave(dirty)` (`src/lib/useConfirmLeave.ts`, react-navigation's `usePreventRemove` from `expo-router/react-navigation`) catches the header back, Android back and the iOS swipe; the page renders its own "Forkaste endringene?" sheet while `asking`, and calls `allowLeave()` right before it navigates away after saving. Jest has no navigator, so `tests/setup/nativeMocks.js` mocks that module (the test reads the recorded callback). The shared sheet is `DiscardChangesSheet` (`src/components/DiscardChangesSheet.tsx`); Rediger profil, the Add wizard (its first step's back included), onboarding, business onboarding, Nytt samarbeid and the listing editor use it (review 2026-11-18 E-06/IJ11, H-12). Rediger profil uses it; its "Forhåndsvis" renders `PersonProfileBody` (`src/features/people/`), the body of every person page.
- **System back (user 2026-11-17, 0454):** Android's back undoes the last step, never more. Tabs go by history (`app/(tabs)/_layout.tsx` `backBehavior="history"`; on Kart with nothing left it closes the app). A multi-step screen calls `useStepBack(active, back)` (`src/lib/useStepBack.ts`) with the same `back` its header ← uses, active from the second step on (onboarding, business onboarding, the Add wizard, Personvernsjekk, Mottilbud); the first step lets the press through to the router and `useConfirmLeave`. A `Sheet` with an `onBack` sends system back there. On the map, back first steps through the detail stack (`mapBackAction`), then lowers a pulled-up browse list to its peek (`browseBackCollapses`). A place or experience picked on Søk opens on the map with the query along (`sq`); back from that sheet returns to Søk with the same results and no keyboard (`resume`, 0469), a pin tapped after it does not. `router.replace` stays only at session boundaries (`resetTo`) and after a finished form (Importer, contact access), each with a comment; everything else is `push`, so back returns to the screen and its state.
- **Settings (Phase 18):** Innstillinger's rows are one list (`SettingsScreen`) that both the groups and the search render; `PAGE_ROWS` in `src/features/settings/settingsIndex.ts` names what each row's page holds, word for word (`tests/settingsSearch.test.tsx` renders every page to check), so rename a row there too. Varsler's switches are one in-memory store too (`src/lib/notificationPrefs.ts`, reset on logout; the hub's Varsler row reads `pushSummary`, review 2026-11-18 IJ4), and Språk og region shows Norwegian only (IJ6). Personvern's switches are one in-memory store (`src/lib/privacyPrefs.ts`, reset on logout) rendered by `privacyRows.tsx` on both Personvern and the Personvernsjekk page (`/settings/privacy-check`). "Nytt i ThirdPlace" (`src/lib/whatsNew.ts`, copy in `src/copy/whatsNew.ts` for the founder to edit) shows once on the map after an app update: the phone keeps the version it last ran with the device settings, a first install records it silently, and it shares the one-hint-per-session slot (`claimSessionSlot`); `thirdplace://_sandbox/simulate` → "Vis på kartet" shows it.
- **Keyboard:** `KeyboardAvoider` / `KeyboardRoot` (`src/components/ui/KeyboardAvoider.tsx`, P10): react-native-keyboard-controller pads inputs + footer frame by frame (also in a `Sheet`’s Modal); the library is required only when its native module is registered, so an older dev client and Jest get React Native’s `KeyboardAvoidingView`.
- **Field types (review 2026-11-18 CMP-11/O9):** `Input`'s `type` (`email`, `url`, `phone`, `password`, `newPassword`, `number`, `handle`) sets the keyboard, autocapitalise, autocorrect and autofill hint; an explicit prop wins. Wizards and onboarding close the keyboard when the step changes.
- **Day labels (review 2026-11-18 JR1):** `whenLabel(experience)` (`src/lib/whenLabel.ts`) is the one way to say when an experience next happens ("I dag 17:30", "I morgen 09:00", "Ons 17:30"); list rows, browse cards, Sveip and the page all use it.
- **Published listings (review 2026-11-18 H-04):** the listing editor's Publiser and Lagre endringer write through `createListing` / `updateListing` in `src/fixtures/created.ts`; Mine annonser and Markedsplass read them again on `useCreatedVersion()`, and logout takes them away with the rest of `created.ts`.
- **Collab deal (review 2026-11-18 #9, founder: deal state + typed signature):** `src/lib/collabDeal.ts` keeps the session's answer to the offer (Godtatt / Avslått / Mottilbud sendt with a counter split) and the name typed to sign the contract; the offer, Samarbeid and Kontrakt read it, and `signOut()` resets it. Nothing is sent or made binding (no collab contract).
- **Sign-up e-mail (review 2026-11-18 #17):** business onboarding stores the e-mail it asked for with `setSignupEmail` (`src/lib/signupProgress.ts`), and "Lag kontoen din" starts with it filled in.
- **System screens:** `app/state/[kind].tsx` (offline/error/maintenance/suspended/update/invite), reachable by deep link `thirdplace://state/<kind>`.
