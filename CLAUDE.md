## What this is

ThirdPlace — an Expo / React Native (TypeScript) mobile client. **Post-restart (2026-10-12) codebase**: a fixtures-only demo of the full UI. No product surface is wired to a real backend yet. Stack: Expo SDK 57 · RN 0.86 · React 19.2 · TS strict · Expo Router (typed routes) · NativeWind v4 · Reanimated 4 + Gesture Handler · TanStack Query (client shell, no endpoints).

```bash

npm test             # jest --ci
npx jest tests/mapAdapter.test.ts         # single test file
npx jest -t "trending sorts"              # single test by name
npx expo-doctor      # dependency/config health (CI runs this; patch drift fails it → `npx expo install --fix`)
```

CI (`.github/workflows/ci.yml`): a **quality** job (format → lint → typecheck → test, Node 22) and a **bundle** job (expo-doctor + `expo export` web & android with `EXPO_PUBLIC_USE_NATIVE_MAP=0`, then a grep over every exported file, the web `.js` and the android Hermes `.hbc` read as text, asserting no `sk.*` token is in the bundles: anchored in every file, a Mapbox `sk.eyJ…` body anywhere, and in the `.hbc` (strings packed back to back) any `sk.` token of 20+ characters; it fails if `dist-android` holds no `.hbc`).

**Line endings:** the working tree is CRLF, the git index is LF, so local `prettier --check` flags every file. Run `npx prettier --write` only on files you touched (a repo-wide write creates EOL-only churn — `git checkout` those). To check what CI sees: `git show HEAD:<file> | npx prettier --stdin-filepath <file> --check`. Edits made after a prettier run (scripts, sed) need re-formatting before commit.

**Editing files:** use the Edit/Write tools for source files, not shell heredocs or `sed`: in this setup Bash heredocs swallow backslashes (regexes and `\n` escapes have broken several times). A scripted replacement over CRLF files must normalise to LF, replace, then restore CRLF.

## Conventions (differ from common defaults)

- **Styling is NativeWind `className`, not StyleSheet.** Tokens come from [src/theme/tokens.js](src/theme/tokens.js) (CommonJS so `tailwind.config.js` can `require` it); read native colour props (Ionicons `color`, Switch `trackColor`, etc.) with `useThemeColors()` — the static `colors` export is the light palette only. Palette = **Airbnb's** (founder 2026-11-06): `ember` #FF385C for text-less pink fills (heart, active tab, dots, selection, logo), `emberStrong` #E31C5F for pink fills with text, `emberText` #DA1249 for pink text, ink #222222, success #008A05; Button `variant="ember"` = the brand gradient (#E61E4D → #E31C5F → #D70466) — no off-palette hex. **Design system:** [docs/design/DESIGN_SYSTEM.md](docs/design/DESIGN_SYSTEM.md) is the rulebook (light **and** dark themes, one open-licence font, `src/components/ui/` primitives, motion/state rules) — rolled out app-wide (Nov 2026); `tests/designGuard.test.ts` enforces the mechanical rules. The app follows the phone's light/dark setting (`DEFAULT_SCHEME_PREFERENCE = "system"`, `app.json` `userInterfaceStyle: "automatic"` — needs a dev-client rebuild to take effect natively); `thirdplace://_sandbox/theme` can force light/dark for checks. Tailwind's numeric spacing scale **does** resolve alongside the named tokens (checked with `tailwindcss/resolveConfig`); Radius tokens are `xs 6 · sm 8 · md 12 · lg 16 · xl 20 · 2xl 28 · full` (`rounded-3xl`, bare `rounded` and `rounded-[…]` fail the guard). Opacity modifiers work on every colour token (CSS-variable colours, e.g. `bg-danger/15`) but only on Tailwind's steps — use multiples of 5 (`/12` silently generates nothing).
- **Motion tokens** in [src/theme/motion.ts](src/theme/motion.ts); honor `useReducedMotion()` from `@/hooks/useReducedMotion` (the phone's setting or Tilgjengelighet's "Reduser bevegelse"; the guard test bans Reanimated's own hook). Text sizes scale with "Større tekst" inside the `Text` primitive (`src/lib/a11yPrefs.ts`). **Haptics at chosen moments only** (user 2026-11-09, "Also key taps", over ledger 0322's no-tap rule; ledger 0355): `src/lib/haptics.ts` names five strengths: `selection` (Sveip's commit line and the chat's swipe-to-reply, both through `runOnJS`; each step of the Avstand and Varighet sliders, the price slider stays silent), `toggleOn` (save/like turning on, in `HeartToggle`, once its press has saved: a guest's press opens sign-in and stays quiet), `tap` (a message sent), `longPress` (`ListRow`'s long-press menu, the chat's reactions) and `success` (joined: `JoinedSheet`; published: the Add wizard). Android uses its own feedback constants (`performAndroidHapticsAsync`, falling back below API 34/30), iOS the matching calls. Plain buttons, navigation, chips and switches stay silent, the ui primitives take no `haptic` prop, and `tests/designGuard.test.ts` holds the allowlist of files and moments.
- **className + Reanimated:** NativeWind styles only core components reliably — `className` on an `Animated.createAnimatedComponent(...)` (even with `cssInterop`) is dropped on a cold start but looks fine after hot reload. Layer instead: core `Pressable` (layout `className`, hitSlop) → `Animated.View` (style only) → core `View` (visual `className`), as in [src/components/ui/Pressable.tsx](src/components/ui/Pressable.tsx) (its press scale is React Native’s core `Animated` with the native driver since 0367: a Reanimated shared value and style per chip and row cost Filtre’s open about 11 %; keep it that way). Verify UI changes after a **cold start** (force-stop + relaunch), not only hot reload.
- **Navigation:** Expo Router, exactly 5 tabs (`app/(tabs)/` map/swipe/add/chat/profile; centre "Legg til" is TikTok’s stacked button in our colours (founder 2026-11-08, `src/components/AddTabIcon.tsx`): an ink face with the plus, an ember layer peeking out on the left and the brand gradient’s magenta on the right, the same whether the tab is open or not (the label turns ember while open); active tab ember). Most surfaces are stack routes in `app/*.tsx` that re-export a screen from `src/features/<domain>/` (`export { default } from "@/features/…"`); map details stay sheets. **Pages, not modals (founder 2026-11-06):** anything you read, browse or fill in over several fields is a stack route with a back button (`/experience/[id]`, `/place/[id]`, `/group/[id]`, `/people/[id]`, …; `routeFor()` in `src/lib/entityRoutes.ts` maps a detail target to its page); a `Sheet` is only for a short choice, picker, confirmation, filter, share/report/block, sign-in prompt or viewer. `Header` back uses `goBackOr()` so a page opened from a cold deep link goes to the map. Every back button shows the same ← (`BACK_ICON` from `src/components/ui`, the arrow of the map's page sheet; user 2026-11-09; `tests/designGuard.test.ts` checks every "Tilbake" button); month arrows ("Forrige måned") keep their chevrons. Use `resetTo(href)` from [src/lib/navigation.ts](src/lib/navigation.ts) at session boundaries (login/logout/onboarding finish) so back can't return to a signed-in screen. Sign-up order (founder 2026-11-06): "Kom i gang" → onboarding → "Lag kontoen din" → code → map (`src/lib/signupProgress.ts`); `register`/`verify-code` sit in the root stack because `resetTo` only pops the focused stack — inside the `(auth)` group it left onboarding behind. Typed routes can lag for new `index` routes — cast with `as Href`.
- **Sheets:** use `Sheet` / `Overlay` from [src/components/ui](src/components/ui) (Modal engine; map sheets use `@gorhom/bottom-sheet` + `useSheetChrome()`) — no raw `Modal` elsewhere. The tap-to-close scrim is a **sibling behind** the card — never wrap buttons in a backdrop `Pressable` (nested `<button>` on web). Don't swap one Modal for another in the same render (iOS refuses) — close, then open after a delay longer than the 200 ms exit. Children mount only while open; for an `Overlay`, render the body unconditionally inside it so the exit animation has content. A `Sheet` or `Overlay` that was never opened renders nothing (no Modal, no presence state; speed pass 0348); once opened, its engine stays mounted for the exit and later opens. Inside a Modal, a React commit drops Reanimated's animated style on Android (the sheet slid off-screen or new content did not paint until a touch), so `Sheet`/`Overlay` switch to a plain style once settled (`usePresence().settled`) — keep that pattern for any animated surface inside a Modal. `InteractionManager` is deprecated in RN 0.86; use a timer. **Keep `package.json` → `reanimated.staticFeatureFlags.FORCE_REACT_RENDER_FOR_SETTLED_ANIMATIONS: false`**: with Reanimated 4.5's default (true) the gorhom sheets opened or snapped by code stayed at the closed position on Android (shared value at the snap, native view not); a static flag change needs a native rebuild. The browse sheet also mounts at its peek with `animateOnMount={false}`.
- **Keyboard:** edge-to-edge Android does not resize the window or a Modal for the keyboard, so `adjustResize` alone does nothing — wrap inputs + footer in `KeyboardAvoidingView behavior="padding"` on both platforms (as `Sheet`, the wizards and the chat thread do). The emulator's hardware keyboard keeps Gboard compact and hides this; test keyboard layouts with `hw.keyboard=no` in the AVD config.
- **Status bar:** `<StatusBarStyle style="light" | "dark" | "auto" />` from `src/components/ui` (focus-aware stack; theme decides when nothing asks) — never `expo-status-bar`'s `<StatusBar>` in a screen: tab/stack screens stay mounted, so its style outlived the screen. `Screen` pads from `useSafeAreaInsets()` (provider seeded with `initialWindowMetrics`).
- UI language is **Norwegian**. Strict TS; `any` only at documented interop boundaries (lazy native requires in `src/lib/haptics.ts`, `useMapLocation`).

## Map feature architecture (spans many files)

The Map is a thin screen ([app/(tabs)/map.tsx](<app/(tabs)/map.tsx>)) composing hooks + components under [src/components/map/](src/components/map). The rules below are the ones that bite on any change; how each part works, and which decision set it, is in [docs/map/MAP_ARCHITECTURE.md](docs/map/MAP_ARCHITECTURE.md). Read it before changing the camera, the sheets, pins, filters or search.

- **Model:** `types/mapPresentation.ts` `DiscoveryItem` (markers, clusters, preview and list all render it) and the six `DiscoveryMode`s in PDF order; `DEMO_MODES` (For deg, Venner) stay non-personalised. Pure services: `services/mapFixtureAdapter.ts` (mode → items, `orderItems`), `mapSearch.ts`, `softClustering.ts`, `itemType.ts`, `pinCamera.ts`, `bounds.ts`.
- **Memo boundaries (speed pass):** `MapCanvas`, `MapboxMap` (+ `PinImages`, `PinsSource`, `UserPuck`), `MapBrowseSheet`, `MapDetailSheet` and `DetailContent` are memoised. Keep every prop from `app/(tabs)/map.tsx` stable (`useCallback`, `useMemo`, the shared `NO_ITEMS`): rnmapbox re-serialises a ShapeSource's whole FeatureCollection and rebuilds every layer style on each render. The live position and heading live in `src/lib/userLocation.ts`; only the location dots subscribe, and `useMapLocation` pauses the watches while the map tab is not focused.
- **Detail sheet:** `MapDetailSheet` (snaps peek · mid · full; a marker tap opens the peek) with a `sheetStack`. Experiences and places open as the page sheet (`ExperiencePage` / `PlacePage` in the app-root portal, full screen at the top snap). It opens in three stages (`sheetStage.ts`): the header and gallery, then the title and first rows once it rests (`useSheetStageFirst`), then the rest (`useSheetStageReady`). **Keep new page sections inside the `first` or `ready` blocks.** The `/place` and `/experience` routes render everything. The floating card (`PageActionCard`) shows only on the full-screen page.
- **Mapbox:** `@rnmapbox/maps` is native-only; [metro.config.js](metro.config.js) aliases it to `mapbox-stub.js` on web or when `EXPO_PUBLIC_USE_NATIVE_MAP !== "1"`; **keep the stub's exports in sync**. Public `pk.*` = `EXPO_PUBLIC_MAPBOX_TOKEN`; secret `sk.*` = `MAPBOX_DOWNLOADS_TOKEN`, native-build input only ([app.config.ts](app.config.ts)). `expo-location`, `expo-haptics` and AsyncStorage are required lazily and guarded. Basemap = map type × time-of-day style (`basemapFor` in `mapStyles.ts`); the `<StyleImport id="basemap" existing config>` that hides POIs **must repeat `lightPreset`** or every style renders as day. Each style load resets heading and pitch to 0.
- **Pins:** paint in `pinStyle.ts` (fill by the interest's category from `mapPalette`, never the brand pink; ring by kind; pink ring only for selection), glyphs only through `PinGlyph`, registered once from `allPinGlyphs()`. Pin, title and cluster layers need emissive strength 1 or they go dark on dusk/night basemaps. The selected pin's ring is set natively from the press (`services/pinSelection.ts`, `setNativeProps`); React's `selectedMarkerId` stays the source of truth, and `onSelectMarker` returns whether it took the selection.
- **Camera:** after the first view the camera is the user's: `<Camera defaultSettings>`, never controlled centre/zoom props. Moves go through `cameraRef` once per request (`useMapCamera().flyTo`), never on a GPS fix. A pin tap moves the camera from the press: zoom to `FOCUS_ZOOM` (13.6) once, then pan only, never out; a list pick or `/map?focus=` link zooms to 15.5 below 15 so the pin leaves its cluster.
- **Distances:** always from the origin store ([src/lib/origin.ts](src/lib/origin.ts)) through `distanceLabelFor(coord, origin)` / `useOrigin()`, never the fixtures' legacy `distance` / `distanceM`. Lists are nearest first, places and experiences mixed (`orderItems`); Sveip decks are built when the tab or filters change, never on an origin move.
- **Filtre:** applied filters show on the map only as the number on the Filtre button; the eight categories are picked only in Filtre's Kategori (no chips on the map or the search page). Each section renders from a `useMemo` keyed on its own filters, with stable callbacks; keep new sections that way. Sveip opens the same `MapFilterSheet`, and experiences go through `applyExperienceFilters` on both surfaces.
- **Labels and search:** item types and their labels come from `services/itemType.ts` (on the map a business, city space or experience says its own kind; Filtre's Type keeps Bedrift/Byrom/Opplevelse/Arrangement). One matcher (`services/mapSearch.ts`) serves the overlay, the map list and `countResults`.

Swipe ([src/components/swipe/](src/components/swipe)): `SwipeDeck` (gesture engine, tabs For deg/Opplevelser/Steder) over pure, tested `deckLogic.ts` / `deckItems.ts` / `useSwipeDeck.ts`; every tab is the same deck over `DeckItem`s. Group swipe is `src/features/groupswipe`.

- Launch the dev client **once** (force-stop first); a second launch intent while starting crashes it ("react context shouldn't be created before"). After it's up, deep links work: `thirdplace://map`, `…://settings`, `…://chat/c1`, `…://state/maintenance`, etc.
- Screenshot: `adb exec-out screencap -p` (strip bytes before `\x89PNG`). Find tap targets with `adb shell uiautomator dump //sdcard/u.xml`. In Git Bash prefix device paths with `//` (MSYS path mangling). Modal content may render a beat after a tap — wait before capturing.
- The host is RAM-constrained: emulator ANRs ("isn't responding", even for System UI) are usually CPU/RAM starvation, not app bugs — confirm via `adb root` + `adb shell cat //data/anr/<newest>` (main thread in `MainActivity.<init>` with no app frames = environment). Killing the process on port 8090 can also kill the adb server (`adb devices` restarts it).
- **Speed measurements (speed pass 0344–0359, reactions pass 0361–0369):** production JS on the dev client (`npx expo start --dev-client --port 8092 --no-dev --minify --clear`, Metro back in dev mode after), a freshly booted emulator for each batch (the emulator process leaks host memory while it renders; after about 25 minutes every number inflates), and CPU time per thread from `/proc` as the before/after measure (frame counts drift with uptime). Method, results and follow-ups: [docs/reviews/PERF_2026-11-09.md](docs/reviews/PERF_2026-11-09.md).
- **Timing a tap (marker tap, 0379–0383):** `adb shell settings put system show_touches 1`, `screenrecord` around one `input tap`, then frames every 50 ms from the touch dot (ffmpeg `fps=20,tile`) to read when the ring, camera and sheet move; temporary `console.log("TPPROBE …" + Date.now())` probes read from `adb logcat -s ReactNativeJS` give the JS timeline (remove them before committing). Measure 5–20 minutes after a fresh boot: taps in the first minutes are 3–5× slower (the emulator's own start-up work). Single runs vary about ±0.1 s, so before calling something a regression, run the old code the same way.
- After `adb shell pm clear com.thirdplace.app` the dev client opens its developer-menu intro once: tap Continue, then close the menu, before the welcome screen shows.
- A full JS reload while the map streams location can crash the dev client natively (`@rnmapbox/maps` 10.3.8 emits through a stale callback: `OutOfMemoryError: bad_array_new_length` in `RNMBXLocationModule`). Production has no in-app reload, so only dev hits it: keep route files to a default export (a named non-component export forces Fast Refresh to reload) and cold start instead of reloading.
- `android/` is generated (gitignored): after a plugin or `app.json` change run `npx expo prebuild --platform android` first (it regenerates the folder). Rebuild the dev client with `npx expo run:android` after any native dependency, Reanimated static flag or native `app.json` change.
- **Patched dependency (0351):** `patches/react-native-screens+4.26.2.patch` is the upstream fix (react-native-screens#4413, released in 4.28.0; SDK 57 pins ~4.26) for a native SIGSEGV in `MountingCoordinator::pullTransaction` on about one cold start in four. `scripts/apply-patches.js` applies it on every install (`postinstall`, so CI and EAS too), stops the install on another version below 4.28.0 or a diff that no longer applies, and `tests/nativePatches.test.ts` fails if it is missing; `.gitattributes` keeps `patches/*.patch` LF. A changed patch needs a dev-client rebuild; remove the patch when the SDK brings 4.28.0 or later.

- **On a real Android phone (2026-11-08):** `eas.json`'s `development` (dev client) and `preview` (standalone) profiles build an installable APK with `EXPO_PUBLIC_USE_NATIVE_MAP=1`; `npx eas-cli build --profile development --platform android --non-interactive --no-wait` uses the remote keystore and the secret `MAPBOX_DOWNLOADS_TOKEN` from the EAS `development` environment. ## PR / change management

Small, reviewable, one-slice commits/PRs, each with a ledger line; keep honesty/not_done fields truthful (say what wasn't emulator-verified). Never auto-merge, force-push shared branches, or deploy. Do not weaken tests to pass CI.
