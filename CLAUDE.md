## What this is

ThirdPlace — an Expo / React Native (TypeScript) mobile client. **Post-restart (2026-10-12) codebase**: a fixtures-only demo of the full UI. No product surface is wired to a real backend yet. Stack: Expo SDK 57 · RN 0.86 · React 19.2 · TS strict · Expo Router (typed routes) · NativeWind v4 · Reanimated 4 + Gesture Handler · TanStack Query (client shell, no endpoints).

CI (`.github/workflows/ci.yml`): a **quality** job (format → lint → typecheck → test, Node 22) and a **bundle** job (expo-doctor + `expo export` web & android with `EXPO_PUBLIC_USE_NATIVE_MAP=0`, then a grep over every exported file, the web `.js` and the android Hermes `.hbc` read as text, asserting no `sk.*` token is in the bundles: anchored in every file, a Mapbox `sk.eyJ…` body anywhere, and in the `.hbc` (strings packed back to back) any `sk.` token of 20+ characters; it fails if `dist-android` holds no `.hbc`).

**Line endings:** the working tree is CRLF, the git index is LF, so local `prettier --check` flags every file. Run `npx prettier --write` only on files you touched (a repo-wide write creates EOL-only churn — `git checkout` those). To check what CI sees: `git show HEAD:<file> | npx prettier --stdin-filepath <file> --check`. Edits made after a prettier run (scripts, sed) need re-formatting before commit.

## Conventions (differ from common defaults)

- **Styling is NativeWind `className`, not StyleSheet.** Tokens come from [src/theme/tokens.js](src/theme/tokens.js) (CommonJS so `tailwind.config.js` can `require` it); read native colour props (Ionicons `color`, Switch `trackColor`, etc.) with `useThemeColors()` — the static `colors` export is the light palette only. Palette = **Airbnb's** (founder 2026-11-06): `ember` #FF385C for text-less pink fills (heart, active tab, dots, selection, logo), `emberStrong` #E31C5F for pink fills with text, `emberText` #DA1249 for pink text, ink #222222, success #008A05; Button `variant="ember"` = the brand gradient (#E61E4D → #E31C5F → #D70466) — no off-palette hex. **Design system:** [docs/design/DESIGN_SYSTEM.md](docs/design/DESIGN_SYSTEM.md) is the rulebook (light **and** dark themes, one open-licence font, `src/components/ui/` primitives, motion/state rules) — rolled out app-wide (Nov 2026); `tests/designGuard.test.ts` enforces the mechanical rules. The app follows the phone's light/dark setting (`DEFAULT_SCHEME_PREFERENCE = "system"`, `app.json` `userInterfaceStyle: "automatic"` — needs a dev-client rebuild to take effect natively); `thirdplace://_sandbox/theme` can force light/dark for checks. Tailwind's numeric spacing scale **does** resolve alongside the named tokens (checked with `tailwindcss/resolveConfig`); Radius tokens are `xs 6 · sm 8 · md 12 · lg 16 · xl 20 · 2xl 28 · full` (`rounded-3xl`, bare `rounded` and `rounded-[…]` fail the guard). Opacity modifiers work on every colour token (CSS-variable colours, e.g. `bg-danger/15`) but only on Tailwind's steps — use multiples of 5 (`/12` silently generates nothing).
- **Motion tokens** in [src/theme/motion.ts](src/theme/motion.ts); honor `useReducedMotion()` from `@/hooks/useReducedMotion` (the phone's setting or Tilgjengelighet's "Reduser bevegelse"; the guard test bans Reanimated's own hook). Text sizes scale with "Større tekst" inside the `Text` primitive (`src/lib/a11yPrefs.ts`). **No vibration on a tap** (founder 2026-11-09): `src/lib/haptics.ts` is only for drag gestures (Sveip's commit-line tick, the chat's swipe-to-reply, through `runOnJS`); the ui primitives have no `haptic` prop, and the guard test enforces it.
- **className + Reanimated:** NativeWind styles only core components reliably — `className` on an `Animated.createAnimatedComponent(...)` (even with `cssInterop`) is dropped on a cold start but looks fine after hot reload. Layer instead: core `Pressable` (layout `className`, hitSlop) → `Animated.View` (style only) → core `View` (visual `className`), as in [src/components/ui/Pressable.tsx](src/components/ui/Pressable.tsx). Verify UI changes after a **cold start** (force-stop + relaunch), not only hot reload.
- **Navigation:** Expo Router, exactly 5 tabs (`app/(tabs)/` map/swipe/add/chat/profile; centre "Legg til" is TikTok’s stacked button in our colours (founder 2026-11-08, `src/components/AddTabIcon.tsx`): an ink face with the plus, an ember layer peeking out on the left and the brand gradient’s magenta on the right, the same whether the tab is open or not (the label turns ember while open); active tab ember). Most surfaces are stack routes in `app/*.tsx` that re-export a screen from `src/features/<domain>/` (`export { default } from "@/features/…"`); map details stay sheets. **Pages, not modals (founder 2026-11-06):** anything you read, browse or fill in over several fields is a stack route with a back button (`/experience/[id]`, `/place/[id]`, `/group/[id]`, `/people/[id]`, …; `routeFor()` in `src/lib/entityRoutes.ts` maps a detail target to its page); a `Sheet` is only for a short choice, picker, confirmation, filter, share/report/block, sign-in prompt or viewer. `Header` back uses `goBackOr()` so a page opened from a cold deep link goes to the map. Use `resetTo(href)` from [src/lib/navigation.ts](src/lib/navigation.ts) at session boundaries (login/logout/onboarding finish) so back can't return to a signed-in screen. Sign-up order (founder 2026-11-06): "Kom i gang" → onboarding → "Lag kontoen din" → code → map (`src/lib/signupProgress.ts`); `register`/`verify-code` sit in the root stack because `resetTo` only pops the focused stack — inside the `(auth)` group it left onboarding behind. Typed routes can lag for new `index` routes — cast with `as Href`.
- **Sheets:** use `Sheet` / `Overlay` from [src/components/ui](src/components/ui) (Modal engine; map sheets use `@gorhom/bottom-sheet` + `useSheetChrome()`) — no raw `Modal` elsewhere. The tap-to-close scrim is a **sibling behind** the card — never wrap buttons in a backdrop `Pressable` (nested `<button>` on web). Don't swap one Modal for another in the same render (iOS refuses) — close, then open after a delay longer than the 200 ms exit. Children mount only while open; for an `Overlay`, render the body unconditionally inside it so the exit animation has content. Inside a Modal, a React commit drops Reanimated's animated style on Android (the sheet slid off-screen or new content did not paint until a touch), so `Sheet`/`Overlay` switch to a plain style once settled (`usePresence().settled`) — keep that pattern for any animated surface inside a Modal. `InteractionManager` is deprecated in RN 0.86; use a timer. **Keep `package.json` → `reanimated.staticFeatureFlags.FORCE_REACT_RENDER_FOR_SETTLED_ANIMATIONS: false`**: with Reanimated 4.5's default (true) the gorhom sheets opened or snapped by code stayed at the closed position on Android (shared value at the snap, native view not); a static flag change needs a native rebuild. The browse sheet also mounts at its peek with `animateOnMount={false}`.
- **Keyboard:** edge-to-edge Android does not resize the window or a Modal for the keyboard, so `adjustResize` alone does nothing — wrap inputs + footer in `KeyboardAvoidingView behavior="padding"` on both platforms (as `Sheet`, the wizards and the chat thread do). The emulator's hardware keyboard keeps Gboard compact and hides this; test keyboard layouts with `hw.keyboard=no` in the AVD config.
- **Status bar:** `<StatusBarStyle style="light" | "dark" | "auto" />` from `src/components/ui` (focus-aware stack; theme decides when nothing asks) — never `expo-status-bar`'s `<StatusBar>` in a screen: tab/stack screens stay mounted, so its style outlived the screen. `Screen` pads from `useSafeAreaInsets()` (provider seeded with `initialWindowMetrics`).
- UI language is **Norwegian**. Strict TS; `any` only at documented interop boundaries (lazy native requires in `src/lib/haptics.ts`, `useMapLocation`).

## Map feature architecture (spans many files)

The Map is a thin screen ([app/(tabs)/map.tsx](<app/(tabs)/map.tsx>)) composing hooks + components under [src/components/map/](src/components/map):

- **Presentation model** — `types/mapPresentation.ts`: `DiscoveryItem` (what markers, clusters, preview and list render) and 6 `DiscoveryMode`s in PDF order (For deg default · Trending · Live · Utforsk · Lagret · Venner); `DEMO_MODES` (For deg/Venner) must stay non-personalized demo shells.
- **Services (pure)** — `services/mapFixtureAdapter.ts` (mode → items), `mapSearch.ts` (grouped search), `softClustering.ts`.
- **Hooks** — `hooks/useMap{Filters,Discovery,Selection,Presentation,Camera,Location,Saved}.ts`. Selection opens the **detail sheet** (`MapDetailSheet`, snaps peek · mid · full; a marker tap opens it at the peek, which is the preview) with a `sheetStack` (push/back via `DetailContentRouter` → `content/*`).
- **Rendering** — `MapCanvas` picks native `MapboxMap` (clustered `ShapeSource`) vs `SoftMap` fallback.
- **Mapbox:** `@rnmapbox/maps` is native-only; [metro.config.js](metro.config.js) aliases it to `mapbox-stub.js` on web or when `EXPO_PUBLIC_USE_NATIVE_MAP !== "1"` (keep stub exports in sync). Public `pk.*` = `EXPO_PUBLIC_MAPBOX_TOKEN`; secret `sk.*` = `MAPBOX_DOWNLOADS_TOKEN`, native-build input only ([app.config.ts](app.config.ts)). `expo-location`/`expo-haptics` and AsyncStorage (`src/lib/deviceSettings.ts`) are required lazily + guarded (AsyncStorage throws on load in a dev client built without it). Basemap: two axes in `mapStyles.ts`: map type (Standard / Satellitt / Terreng, founder 2026-11-07) × time-of-day style (the four Studio styles, Mapbox Standard with dawn/day/dusk/night presets, or Auto); `basemapFor(type, styleKey)` gives the URL, preset, dark flag and terrain flag. Dense maps: titles from zoom 13 with `symbolSortKey` = list rank, glyphs from zoom 11 (plain dots below), cluster bubbles step at 10/50/100, the selected pin and its title redrawn on top; `thirdplace://_sandbox/pins` shows all 84; titles sit below the glyph layer (Mapbox places upper symbol layers first) and turn light on a dark halo at dusk/night; keep `mapbox-stub.js` exports in sync. Every style load resets heading and pitch to 0 (the Studio styles carry the camera they were saved with), so each style opens north up and flat; rotate and tilt gestures are on (founder 2026-11-07). After the first view the camera is the user's: `<Camera defaultSettings>`, not controlled `centerCoordinate`/`zoomLevel` props (a new centre array on any render re-applied them), and Posisjon or an area flies once per `recenterSignal`, never on a GPS fix.
